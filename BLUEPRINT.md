### How to build and test

- The Xcode project is **generated** from `project.yml` with XcodeGen. Edit `project.yml`, never the `.pbxproj`, and run `xcodegen generate` after adding or removing files. The generated `CountEmBlessingz.xcodeproj` is committed so the project opens without XcodeGen.
- Unit tests (fast, about 5 seconds): `xcodebuild test -project CountEmBlessingz.xcodeproj -scheme CountEmBlessingz -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max'`
- UI tests (2 to 4 minutes, Debug build only): same command with `-scheme CountEmBlessingzUI`.
- Release build check: `xcodebuild build -configuration Release -destination 'generic/platform=iOS Simulator'`. It must stay free of warnings and of debug-only code.
- DEBUG-only launch arguments (compiled out of Release): `-seedDemo` (in-memory demo data, already onboarded), `-demoTheme jade|grand|quiet`, `-demoTab 0..3`, `-demoImport` (opens a sample import review), `-demoFileCurrency USD`, `-demoImportSearch text`, `-uiTesting` (empty in-memory store, first launch).

### Added beyond the blueprint

- Merge import: share entries as a `.blessingz` file and merge files from other phones with a review screen (section 18).
- Share buttons: Home header and Settings, through the system share sheet (WhatsApp, Telegram, Mail, AirDrop, Files).
- UI tests (XCUITest) and a separate `CountEmBlessingzUI` scheme.
- Tabs keep their place: a visited tab stays alive, so an open profile, scroll position, search and filters survive switching tabs.
- Large text support: layouts adapt at accessibility sizes, and the tab bar, avatars and the donut centre cap their text size.
- Number handling: strict locale-aware parsing of typed amounts (grouping like "1,000" is understood, junk like "12abc" is rejected).
- Import safety: snapshot before every import, undo for 7 days, validation of hand-made files.

### Deviations from this blueprint

1. **XcodeGen** creates the project (section 4 describes the Xcode wizard).
2. **Swift 5 language mode**, not Swift 6, to avoid strict-concurrency friction with SwiftData.
3. **Fonts** (section 8.3): Google publishes these families only as variable fonts, so the 14 static faces were cut from them with `fonttools`. PostScript names differ from a plain download: Jost and Playfair Display carry a `Roman` infix (for example `JostRoman-Bold`).
4. **Donut** (section 9.5): the hole size comes from each theme's `donutThickness` token instead of a fixed `innerRadius` ratio of 0.62.
5. **Reminder permission** (section 6): also requested the first time a blessing is saved while reminders are on, because the default delay is 3 days and a user would otherwise never be asked. It is still never requested at launch.
6. **Backup file**: backup, restore and sharing use one `.blessingz` file (schema 2) instead of the plain JSON of section 6. Old schema 1 JSON backups still restore.
7. **Sharing a file**: entries use `ShareLink`. CSV and backup use a system share sheet wrapper, because the file is created on tap.
8. **Hide amounts**: the Home chip and the Settings "Hide amounts by default" toggle are the same stored setting.
9. **Tab bar**: re-tapping the tab you are on does nothing (it does not pop to the root).
10. **Occasion raw values**: those listed explicitly in section 5 are as written (for example "Chinese New Year"); the others use their case name (for example `birthday`). Display text always comes from `title`.
11. **Photos** are downscaled to at most 1600 px and stored as JPEG.
12. **Renaming a person** does not change their entries' `updatedAt`, so a rename alone is not part of "changes since last export".
13. **App icon** (section 15): superseded, see the note there.

### Known limitations and not yet verified

- **Not tested on a real iPhone**: Face ID, notification delivery, widget refresh, AirDrop, and handing a file to WhatsApp or Telegram. The simulator has none of these apps.
- **"Share changes since last export"** moves its marker when the system asks for the file, because `ShareLink` cannot report that sharing finished. If a share sheet is opened and then cancelled after the system asked for the file, those changes are left out of the next "since" file. "Share all" always works and merging twice is harmless.
- **Undo last import** restores the whole snapshot, so anything added or changed after the import is lost. The confirmation says so.
- **App Group and signing**: the store lives in an App Group container so the widget can read it. A free personal team cannot use App Groups, so a device build needs a paid team. If the group is unavailable the app falls back to a private store and the widget shows nothing.
- **Privacy**: the Hall of Fame milestone strip and the milestone toast reveal coarse magnitude even with amounts hidden. Reminder notifications show the person's name on the lock screen. The store uses iOS default file protection (readable after first unlock) so the widget can refresh.
- **Not done**: the manual checklist in section 13 (small and large screens, VoiceOver walk-through, airplane-mode pass on a device), keyboard behaviour of the custom tab bar while typing in the Home search field, and the App Store steps in section 16 (including setting `ITSAppUsesNonExemptEncryption` to `NO`, a signing team, a real bundle id, the privacy policy and support pages).
- **English only**, as decided in section 2.

## 1. What the app is

A private, offline iPhone app to track a "honeypot": money people have blessed the user with (angpao, birthday gifts, wedding gifts, and so on), and who gave what.

- One long list of blessings, newest first, grouped by month.
- A "+" button to add: name, amount, occasion. The timestamp is logged automatically.
- Analytics: a pie (donut) chart of the allocation by person, month or occasion.
- Blesser profiles, a Hall of Fame, milestones, thank-you reminders, export and backup.
- All data lives on the device. No cloud, no account, no analytics SDK, no network calls.
- Three swappable visual "vibes" (themes) chosen in onboarding and Settings.

Non-goals: multi-user, sync, budgeting, spending or outflows, currency live-rate lookup, iPad or Mac layouts.

## 5. Data model (SwiftData)

```swift
import SwiftData
import Foundation

@Model
final class Blesser {
    @Attribute(.unique) var id: UUID
    var name: String
    var nameKey: String            // name.trimmed.lowercased(), used for matching
    var thankYouPending: Bool      // true after a new blessing until user marks thanked
    var createdAt: Date
    @Relationship(deleteRule: .cascade, inverse: \Blessing.blesser)
    var blessings: [Blessing] = []

    init(name: String) {
        self.id = UUID()
        self.name = name.trimmingCharacters(in: .whitespacesAndNewlines)
        self.nameKey = self.name.lowercased()
        self.thankYouPending = true
        self.createdAt = .now
    }
}

@Model
final class Blessing {
    @Attribute(.unique) var id: UUID
    var amount: Decimal                  // in the CURRENT currency (AppSettings.currencyCode)
    var currencyCode: String             // ISO 4217; kept equal to current currency
    var date: Date                       // auto-set to now, editable
    var occasionRaw: String              // Occasion.rawValue
    var methodRaw: String                // PaymentMethod.rawValue
    var note: String
    @Attribute(.externalStorage) var photoData: Data?
    var originalAmount: Decimal?         // set on first currency conversion, never overwritten
    var originalCurrencyCode: String?
    var blesser: Blesser?

    var occasion: Occasion { get { Occasion(rawValue: occasionRaw) ?? .other } set { occasionRaw = newValue.rawValue } }
    var method: PaymentMethod { get { PaymentMethod(rawValue: methodRaw) ?? .cash } set { methodRaw = newValue.rawValue } }
}

@Model
final class AppSettings {                // exactly one row; create on first launch
    var hasOnboarded: Bool = false
    var countryCode: String = "MY"       // ISO 3166 alpha-2
    var currencyCode: String = "MYR"
    var themeID: String = "jade"         // "jade" | "grand" | "quiet"
    var faceIDEnabled: Bool = false
    var hideAmounts: Bool = false
    var goal: Decimal = 20000
    var reminderDays: Int = 3            // 0 = reminders off
    init() {}
}

@Model
final class CurrencyConversion {         // audit log, one row per currency change
    var date: Date
    var fromCode: String
    var toCode: String
    var rate: Decimal                    // 1 from = rate to
    var convertedAmounts: Bool           // false = label-only change
    var count: Int
    init(date: Date = .now, fromCode: String, toCode: String, rate: Decimal, convertedAmounts: Bool, count: Int) {
        self.date = date; self.fromCode = fromCode; self.toCode = toCode
        self.rate = rate; self.convertedAmounts = convertedAmounts; self.count = count
    }
}
```

**As built (additions to the models above):** `Blessing.updatedAt: Date` (default `.now`, set on every edit, currency conversion and person merge; merge import compares it). `AppSettings.deviceID: UUID` (identifies this phone in exchange files and survives "Erase all data"), `AppSettings.deviceLabel: String` (the sharing name; empty means the device name) and `AppSettings.lastExportAt: Date?`. All have defaults, so existing stores migrate automatically (checked by installing over an old store). `AppSettings.resetToDefaults()` backs "Erase all data". The store itself is created by `SharedStore.makeContainer()` in an App Group container.

Enums (plain `String` raw values, `CaseIterable`):

- `Occasion`: `chineseNewYear = "Chinese New Year"`, `birthday`, `wedding`, `hariRaya = "Hari Raya"`, `christmas`, `promotion`, `justBecause = "Just because"`, `other`. Provide a `title` string.
- `PaymentMethod`: `cash`, `eWallet = "E-wallet"`, `bank`.

Rules:
- `Blessing.amount` must be greater than 0. Validate in the editor, not in the model.
- Matching a typed name to an existing `Blesser` goes through `BlesserResolver` (case-insensitive, trimmed). Never create two blessers with the same `nameKey`.
- Deleting a blessing leaves the blesser if they still have other blessings. If a blesser ends up with none, delete them too.
- Create the single `AppSettings` row in `RootView` on first appearance if the query returns empty.

## 6. Services

**MoneyFormatter**: `format(_ d: Decimal, currency: String) -> String` using `Decimal.FormatStyle.Currency(code:)` with `.precision(.fractionLength(0...2))`, and zero decimals for currencies with no minor unit (JPY). Also `plain(_:)` (number only, for list rows that show the amount without a symbol). When `AppSettings.hideAmounts` is on, all views show `••••` and apply `.blur` plus `.privacySensitive()`.

**CountryCatalog**: build the country list from `Locale.Region.isoRegions` (or `Locale.isoRegionCodes` for older APIs), map each to its currency via `Locale(identifier: "en_\(code)").currency?.identifier`, drop entries with no currency. Default selection is `Locale.current.region`. Provide search by country name.

**CurrencyConverter**: see section 7.

**MilestoneService**: thresholds `[1_000, 5_000, 10_000, 20_000]` plus the user's goal. `crossed(before:after:) -> Decimal?` returns the highest threshold crossed by an add. Thresholds are in the current currency units, and are not rescaled on conversion.

**ExportService**
- CSV: columns `date(ISO8601),name,amount,currency,occasion,method,note`. Write to a temp file and present with `ShareLink`.
- JSON backup: Codable `BackupFile { schemaVersion: Int; exportedAt: Date; settings; blessers; blessings; conversions }`, `schemaVersion = 1`. Photos are base64 inside the JSON.
- Restore: `.fileImporter` for `.json`. Show a confirmation ("Replace everything on this device?"). Replace, not merge, in v1. Validate `schemaVersion`.

**BiometricLock**: `LAContext.evaluatePolicy(.deviceOwnerAuthentication, ...)`. Lock on scene `.background`, require auth when `.active` again. Cover the app with a privacy view while `.inactive` so the app switcher snapshot shows nothing sensitive.

**ReminderService**: `UNUserNotificationCenter` local notifications only. Request permission the first time the user turns reminders on (not at launch). Schedule one notification per pending blesser, `reminderDays` after the blessing date, text: "Say thanks to {name}." Cancel on mark-thanked, delete, or reminders off. Notification identifier: `thank-{blesser.id}`.

## 7. Currency and conversion

The user picks a country in onboarding, which sets `currencyCode`. Later they may change country in Settings. Because a different currency means the stored numbers are no longer meaningful, the app asks for an exchange rate.

**Flow (Settings, Country row)**
1. User picks a new country. The setting is not applied yet. Present `CurrencyRateSheet`.
2. Sheet text: "Switching from MYR to USD. Enter the rate so your existing amounts convert. Fill in one side, the other side is 1."
3. Two sides shown left to right: `1 MYR  =  [ ? ] USD`. The side the user types in is the input; the other side is fixed at `1 <code>`.
4. A "Swap sides" button flips to `[ ? ] MYR  =  1 USD` and clears the field. Internally: direction `.fromToTo` gives `rate = input`; direction `.toToFrom` gives `rate = 1 / input`.
5. Live preview: "MYR 9,776 becomes USD 2,053" using the entered rate.
6. Primary button "Convert N blessings". Secondary "Keep the numbers, change the label only". Cancel leaves everything unchanged.
7. Input must be a positive decimal. Accept `,` and `.` per locale (parse with `Decimal(string:locale:)`). Show inline error text otherwise.

**Apply (`CurrencyConverter.apply`)** in one `modelContext` transaction:
- For each `Blessing`: if `originalAmount == nil`, set `originalAmount = amount` and `originalCurrencyCode = currencyCode`. Then `amount = round(amount * rate, to: target minor units)` using `NSDecimalNumber` rounding mode `.plain` and scale 0 for JPY, 2 otherwise. Set `currencyCode = target`.
- `AppSettings.goal = max(100, round(goal * rate to nearest 100))`.
- Update `AppSettings.countryCode` and `currencyCode`.
- Insert a `CurrencyConversion` log row.
- "Label only" path: same, but skip the multiplication (rate treated as 1, `convertedAmounts = false`).
- Show a toast: "Converted at 1 MYR = 0.2100 USD."

Display: if `originalAmount` exists and differs, the blessing detail shows a small "Originally MYR 888" line.

## 8. Theme system

Three themes swap at runtime and are stored as `AppSettings.themeID`. One set of views, driven by tokens. No separate view trees per theme.

### 8.1 AppTheme

### 8.3 Fonts

Bundle these open-licence (OFL) Google Fonts as `.ttf` in `Resources/Fonts/` and list them in `UIAppFonts`: Playfair Display (500, 700), Montserrat (400, 500, 600), Jost (400, 500, 700, 800), Cormorant Garamond (500, 600), Inter (400, 500, 600). Include each font's OFL licence text in `Resources/Fonts/LICENSES/`. After adding, print `UIFont.familyNames` and fontNames once in DEBUG to confirm the exact PostScript names, then reference them in `Fonts.swift`. Use `Font.custom(_, size:relativeTo:)` so Dynamic Type works. Provide a system-font fallback if a face fails to load.

### 8.4 Signature effects (fire when an add crosses a milestone)

- `coinRain` (Jade): about 24 gold circles fall from the top over about 2 s with random delays and positions. Use `TimelineView` plus `Canvas`, or simple `withAnimation` offsets. Non-interactive overlay.
- `chapterCard` (Grand): a full-screen dim overlay with a centered card "CHAPTER 10k / The pot grows" in a double border, shown about 2.2 s.
- `countUp` (Quiet): the hero total animates from the old to the new value over about 0.9 s using `.contentTransition(.numericText())` or a manual timer. Quiet runs this on every add, not only milestones.
- Respect `accessibilityReduceMotion`: skip animations and show only the toast.
- Add a medium haptic (`UIImpactFeedbackGenerator`) on save, and a success notification haptic on milestones.

5. **Privacy.**

## 18. Merge import (as built)

Goal: several people record blessings on their own phones, then combine them by sharing a file. No cloud, no account, no network. Deletes stay local: an import only adds or updates entries and never deletes or carries a deletion over.

### 18.1 Data

- `Blessing.updatedAt` and `AppSettings.deviceID`, `deviceLabel`, `lastExportAt` (section 5 note).
- Settings, General: "Sharing name" is the name other people see ("From Dad's phone").

### 18.2 The exchange file

- Extension `.blessingz`, JSON, type id `com.example.countemblessingz.exchange` (conforms to `public.json`), declared in `Info.plist` so tapping the file in AirDrop, Messages, Mail, WhatsApp or Files opens the app. `LSSupportsOpeningDocumentsInPlace` is `false` (the file is copied and reviewed).
- Fields: `schemaVersion` (2), `exportedAt`, `exportedBy`, `deviceID`, `currencyCode`, `kind` (`full` or `sinceLastExport`), `blessers` (id, name, nameKey) and `blessings` (id, blesserID, amount, currencyCode, date, occasion, method, note, updatedAt, photo as base64). Dates are ISO 8601 with milliseconds, always rounded down so an unchanged entry never looks newer after a round trip. Amounts are written as text ("186.48"), never as floating point.
- Optional **backup extras**, only in the lossless backup: settings, conversion log, each person's `thankYouPending` and `createdAt`, each entry's `originalAmount` and `originalCurrencyCode`. Merge import ignores them. "Share all my entries" leaves them out, so settings and thank-you flags are not sent to other people.
- Restore (Settings, Data) replaces everything and keeps this phone's `deviceID` and sharing name. It also reads old schema 1 JSON backups. Import (merge) refuses schema 1 with "This is an older backup. Use Restore from backup instead."
- Friendly errors, nothing changes: "This isn't a Count 'Em Blessingz file.", "This file is from a newer version of the app.", "This file is damaged, so nothing was changed.", "That file couldn't be read.", "That file is too large to be a Count 'Em Blessingz file."
- Files are validated before anything is read into the database: unique ids, every entry points at a listed person, people need a name (500 characters at most), amounts from 0 to 1 trillion, notes up to 20,000 characters, at most 100,000 people and 500,000 entries, and files over 250 MB are refused unread. Money text is parsed strictly. Only file links are accepted from the system.

### 18.3 Sharing

- Settings, Data and the Home header: **Share all my entries** and (Settings only) **Share changes since last export**, through the system share sheet. The files are prepared in the background and kept current.
- "Changes" means entries whose `updatedAt` is after `lastExportAt`. When the system asks for a changes file, `lastExportAt` becomes the time that file was built, so edits made while the sheet was open are still included next time. It never moves backwards.
- Settings, Data also has **Import from file**.

### 18.4 Duplicate detection (`DuplicateDetector`, pure functions)

Person matching, in order: same person id, same normalised name (trimmed, spaces collapsed, lowercase, diacritics removed), a **similar** name (edit distance 2 or less, or one contains the other, both at least 4 characters), otherwise a new person. A similar name is never merged automatically; the review screen asks, defaulting to "Keep separate".

Entry status (`duplicateWindow` = 72 hours, inclusive):

| Status | Rule | Default |
|---|---|---|
| Already in your pot | Same id and the incoming `updatedAt` is not newer (or nothing differs) | Unticked and locked |
| Updated | Same id, newer `updatedAt` and something changed; old and new values are shown | Ticked |
| Possible duplicate | Different id, same person, same amount (after conversion, rounded to the currency's minor unit), dates within 72 hours | Unticked, can be ticked |
| Duplicate in file | Two entries in the file for the same person and amount within 72 hours; the later one is flagged | Unticked |
| New | Everything else, including the same amount a year apart | Ticked |

### 18.5 Import flow (`ImportService`)

1. **Plan** (`buildPlan`) reads the pot and the file and writes nothing. The plan is a plain value: ticks, person choices and the exchange rate re-run detection without touching the database.
2. **Currency**: if the file's currency differs, the user picks an exchange rate (the same swap-sides sheet as Settings) or "Import the numbers as {local currency}". Detection runs after conversion. Converted entries keep `originalAmount` and `originalCurrencyCode`. Until a choice is made, amounts are shown in the file's currency and Import is disabled.
3. **Commit** (only when Import is tapped): first a full snapshot is written to Application Support (last 3 kept, file-protected, excluded from device backups); then everything is written in one transaction. People with no selected entry are not created. New people keep the file's id and name and start with `thankYouPending = false`; existing people's flags are untouched; no reminders are scheduled. Then the milestone check runs on the total before and after, and the theme effect fires once if a threshold was crossed. A toast says "Imported N blessings." with Undo.
4. **Undo last import** (Settings, Data) restores the newest snapshot, offered for 7 days or until the next import.

### 18.6 Review screen

Themed like the other screens. Header "From {name} · exported {date}" and a summary ("7 in file: 3 new, 1 updated, 2 possible duplicates, 1 already in your pot."). Currency banner when the currencies differ. Filter chips (All, New which also includes updates, Possible duplicates, Already in pot), search, and a menu (Select all new, Select all, Select none). Entries are grouped by person with a tri-state checkbox, a chip (New person, Existing person, or "Looks like {name}" with Same person or Keep separate) and, for any matched person, "{n} blessings · Last: {amount} · {occasion} · {date}". Possible duplicates show "Matches {amount} · {occasion} · {date} ({n} days apart)". A sticky footer shows "Import {selected} of {selectable} · {sum}" and Cancel; at accessibility text sizes it shrinks to one button and Cancel moves to the header. Nothing is written until Import. Hide amounts is respected everywhere, including the exchange-rate preview. Each row is a single VoiceOver switch whose label includes the status.
